## [Unreleased]

### Added
- **Workflow & node editing UX** (fixes four `/flows` gaps): (1) **Delete/archive a workflow** — the `/flows` header gains **Rename** + **Delete** for the selected workflow, with a named confirm dialog ("Delete workflow 'X'?", never one-click). The **backend decides** delete vs archive: a history-free draft is hard-deleted, but a workflow with any published version or run is **soft-archived** (`archived_at`) so immutable versions and run/approval audit records are never destroyed; the UI says which happened. Only `flow_*` tables are touched — the legacy `agent_flows` system is untouched. (2) **Delete a canvas node** — select a node → **Delete node** button (danger) or **Delete/Backspace** key removes the node **and every connected edge** (no dangling edges), on the draft only; the keyboard path is guarded so Backspace while typing in an input edits text instead of deleting the node (React Flow's built-in delete key is disabled in favor of this deterministic path). (3) **Input node editing** — the inspector clarifies the Input node's **default value** ("fallback when the run's Starting Input is empty") vs the runtime Starting Input box, keeping the two concepts separate. (4) **Per-node description** — every node type gains an optional `description` in the inspector (label/name + description round-trip through Save/Publish). New pure modules `lib/flows/graph-ops.ts` (node/edge removal + keyboard-delete guard) and `lib/flows/workflow-admin.ts` (the delete-vs-archive service). See `docs/DECISIONS.md` D21.
- **Human Approval node + durable pause/resume** (Phase E): a workflow can now include a **Human Approval** node — a human gate kept strictly separate from the machine-logic Decision node. When a run reaches one it opens a `pending` approval and **pauses durably** (run status `waiting_approval`), surviving browser refresh, navigation, Next hot-reload, and full process restart (the reconciler leaves waiting runs alone; only `running` runs go `interrupted`). `resumeWorkflowRun(runId)` reloads the **immutable** version, rebuilds scheduler state from the persisted node runs, applies the human decision, and continues **without re-running any succeeded node** (no upstream LLM/tool re-calls — proven by an executor call-count test). Approval routes exactly like a Decision: approve activates only the approve-route edge, reject only the reject-route edge (a rejection is a normal outcome down the reject branch, **not** a `failed` run; the node gets a distinct `rejected` status). Resolution is **idempotent** — a conditional `UPDATE … WHERE status='pending'` means approving twice resolves once and resumes once; the process-wide active set is the resume lock. New APIs: `GET /api/flow-approvals` (inbox), `GET /api/flow-approvals/:id`, `POST /api/flow-approvals/:id/approve|reject` (Zod; the client sends only id + decision + optional note — the run/workflow/routes come from the persisted row, never the client). New **Approvals** inbox page + Run Inspector waiting/resolved states + canvas approval-node config. Hermes-originated approval events still surface as `hermes_approval_required` and are **never auto-answered**; resuming a Hermes *session* mid-turn is explicitly **deferred** (no verified serve continuation RPC) — native Approval nodes are the supported durable gate. See `docs/DECISIONS.md` D20.
- **Selectable `hermes serve` production transport** (HRA-2 H3): agent traffic can be routed through Hermes's own WebSocket/JSON-RPC `serve` runtime, chosen in `getHermesClient(db)` via `meta.hermes_production_transport` (**default stays `acp`**). Flipping to serve is **eligibility-gated** (runtime healthy + Hermes-shaped `/api/status` + token configured) with an always-available ACP rollback; **no silent fallback** (a serve failure surfaces `hermes_unavailable`). One isolated serve session per agent-node run, **bounded concurrency** (sessions run independently), layered timeouts (connect/request/inactivity) with `session.interrupt` on timeout, and approval events surfaced as `hermes_approval_required` (never auto-answered — Phase E). Live-validated incl. the Gmail workflow (~114s success, health channel healthy throughout, no ACP-style poisoning). Settings ▸ Hermes Runtime gains a transport selector. See `docs/DECISIONS.md` D19.
- **HermesRuntimeManager + Settings ▸ Hermes Runtime** (HRA-2 H2): backend `lib/connectors/hermes-runtime.ts` discovers the local Hermes binary (validated by `--version`), probes serve health via `GET /api/status` (never `serve --status`), and models runtime state/mode/**ownership** — a 200 on the port is not ownership; only a process IGRIS launched with a live PID is `managed`. Optional managed start/stop is PID-exact (never `serve --stop`, never an external/shared server). `GET/POST /api/settings/hermes-runtime` (Zod) + a truthful Settings panel (install/version/path, endpoint, health, tri-state capabilities, token **presence-only**, ACP-is-production banner, persistent-memory boundary). Non-secret config in the `meta` KV (no migration); serve token in `.env.local` only. Orthogonal to production traffic — the ModelRouter still uses ACP. See `docs/DECISIONS.md` D18.
- **HermesClient seam** (HRA-2 H1): a canonical `chat`/`health`/`capabilities` application seam (`lib/connectors/hermes-client.ts`) that the ModelRouter's `hermes` strategy now calls, decoupling the app from ACP-specific details. Production behavior is unchanged — it wraps the active brain (ACP by default). Plus a **test-only** `HermesServeTransport` (`lib/connectors/hermes-serve.ts`) implementing the same interface over the H0-verified `serve` protocol, proven against an in-memory fake fixture — **not wired to production traffic**. Capabilities are tri-state (MCP/skills stay `unknown`). See `docs/DECISIONS.md` D17.
- **Workflow logic engine** (Phase D): the execution engine gained structured field mapping, `{{Node.field}}` references, Decision/Router nodes with a safe condition evaluator, conditional edges, Transform nodes, and Parallel/Join with deterministic branch/join semantics. Executable node types are now Input, Agent, Output, Transform, Decision, Parallel, Join. New shared modules: `lib/flows/references.ts` (reference/template resolver), `lib/flows/conditions.ts` (condition schema + evaluator, one evaluator for both Decision and conditional edges), `lib/flows/inputs.ts` (edge-mapping → resolved node input); executors `transform/decision/parallel/join`. Skipped-vs-failed node semantics, active-edge scheduling, and unreachable-node skipping. Canvas node/edge inspectors (Decision rules, Transform config, edge mapping + condition builder) and Run Inspector shows selected routes + skip reasons.
- **G-Brain Flow orchestrator** (`/flows`): multiple named workflows, typed nodes/edges, editable drafts, immutable published versions, validator. (Phase A)
- **Unified model runtime**: `ModelRouter` with `fixed | hermes | auto` strategies; per-agent model configuration UI; provider connect/test/enable/disable; providers Google, NVIDIA, Ollama (local), and custom OpenAI-compatible added; model badges on flow agent nodes. (Phase B)
- **Workflow execution engine + Run Inspector** (Phase C): Input/Agent/Output nodes execute in dependency order through the `ModelRouter`; persisted run + node-run history; in-process run coordinator with polling; Run Inspector panel, canvas run-status overlay, starting input, run history; Save vs Publish vs Run distinction.
- **AI-developer handoff package**: `AGENTS.md` (platform-independent) + `docs/AI-HANDOFF.md`, `PHASE-STATUS.md`, `DATA-MODEL.md`, `CODING-METHODOLOGY.md`, `TESTING-GUIDE.md`, `EXTENDING.md`, `SECURITY.md`, `LEGACY.md`, `DECISIONS.md`, `NEXT-AI-PROMPT.md`, `RELEASE-PROCESS.md`, `INCIDENTS.md`, `CHANGE-LOG.md`, and this `CHANGELOG.md`.

### Changed
- Per-agent chat now executes through the unified `ModelRouter` (previously direct/brain routing). (Phase B)
- The Agent Flow canvas was **removed from `/brain`**; `/brain` is now knowledge-only. Orchestration lives on `/flows`.
- Architecture doc (`docs/ARCHITECTURE.md`) updated through Phase C.

### Fixed
- **Hermes ACP timeout no longer poisons the persistent process.** On a per-prompt timeout the client now sends `session/cancel` and cleans up the leaked request correlation (and always clears the timer), so the shared `hermes acp` process is freed and the next request can succeed. Setup requests (`initialize`/`session/new`) are now timeout-bounded, and safe diagnostics were added (request/session id, elapsed, timeout, process-alive — never prompts/keys). New env: `HERMES_ACP_ARGS`, `HERMES_ACP_DEBUG`. Timeout failures still surface as `hermes_unavailable` with no silent model fallback. (See `docs/INCIDENTS.md` INC-005.)
- Flow runs were falsely marked `interrupted` while still running — the in-process active-run registry was not shared across Next.js per-route bundles. Pinned it to `globalThis`. (See `docs/INCIDENTS.md` INC-001.)
- Canvas node "Delete" previously deleted the underlying agent everywhere; split into non-destructive **Remove from canvas** vs a clearly-labeled two-step **Delete agent**. (INC-004)
- Provider connection status no longer shows a false "connected" from mere key presence; a real backend check is required (`unverified`/`connected` states). (INC-003)

### Database
- Added `flow_approvals` (Phase E) + indexes `idx_flow_approvals_run`, `idx_flow_approvals_status`, `idx_flow_approvals_node_run`. Additive/idempotent (`CREATE TABLE IF NOT EXISTS`); no existing table or column changed. `context_json` stores **non-secret** workflow data only. Run status gained `waiting_approval`; node-run status gained `rejected`.
- Added `flow_workflows`, `flow_versions` (Phase A).
- Added `model_provider_connections` — metadata/status only, **no secret column** (Phase B).
- Added `flow_runs`, `flow_node_runs` + indexes `idx_flow_runs_workflow`, `idx_flow_node_runs_run` (Phase C).
- **Phase D added NO tables or columns** — logic lives in the version graph JSON; runtime detail (selected route, transform result, join branches, skip reason) rides in existing `flow_node_runs.output` / `error_code` JSON fields.
- All additive, idempotent, non-destructive. Legacy `agent_flows` retained and imported once into `wf-main`.

### Security
- **Approval endpoints are backend-authoritative:** the client sends only the approval id, the decision, and an optional note — the run id, workflow, node, and routes are read from the persisted row, so a client can never make one approval resolve a different run. Approval `context_json` holds non-secret workflow data only (never credentials/tokens); the `secret.request` value is never displayed. Human Approval nodes and Hermes `approval/sudo/secret.request` events are **never auto-approved** — only a human resolves them.
- Provider API keys live only in `.env.local`; the DB stores presence/status, never the value; frontend receives `hasCredential` only.
- Provider/adapter errors are redacted before persistence/surfacing.
- Blank credential on update does not erase or reveal a stored key.

### Deprecated
- Legacy Agent Flow: `components/AgentFlowCanvas.tsx`, `app/api/agent-flows/*`, `lib/agents/flow-run.ts`, table `agent_flows` — kept operational for backward compatibility; not for new work. See `docs/LEGACY.md`.

### Known Issues
- **HRA-2:** `hermes serve` is now a **selectable** production transport (H3) but **ACP remains the default**; serve is not the default for anyone. Conditions before serve could become a default: **MCP-specific execution over serve not isolated** (server-side tools incl. real email DID run) → MCP partial; **skills parity unverified**; **persistent-memory isolation** via a dedicated Hermes profile is a pending product decision (Hermes memory persists across sessions, independent of IGRIS G-Brain). Remote Hermes (H4) not implemented.
- Workflow execution is sequential (Parallel branches run in a deterministic order, not truly concurrent — correctness over literal simultaneity). Memory (Phase F) nodes remain placed-but-rejected-before-run; Approval nodes are now runnable (Phase E). Approvals have no expiry/TTL yet (`expired` status is defined but never produced) and no auth layer (resolver actor is `local_operator`).
- Static reference validation checks only the reference ROOT (that the source node exists); deeper runtime paths cannot be proven at publish time.
- `auto` model strategy is a stub (fails `auto_not_implemented`); no fallback/retries/cancel.
- Hermes ACP reports no token usage → node token counts `null`; estimated cost `null` (no fabricated pricing).
- Stale-run detection is on read (→ `interrupted`); no background sweeper or auto-resume.
- Two seed/api render tests are intermittently flaky under full-suite parallel load (pass in isolation / on re-run).
